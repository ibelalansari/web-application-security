# References

## 1. PortSwigger Web Security Academy — Access Control

PortSwigger's Access Control learning material explains how applications
restrict what authenticated users are allowed to do and access.

Official resource:

https://portswigger.net/web-security/access-control

---

## 2. PortSwigger — User ID Controlled by Request Parameter

This is the specific lab used for this exercise.

Official lab:

https://portswigger.net/web-security/access-control/lab-user-id-controlled-by-request-parameter

---

## 3. OWASP — Broken Access Control

OWASP documents Broken Access Control as a major web application
security risk and provides guidance on preventing unauthorized access.

Official resource:

https://owasp.org/Top10/A01_2021-Broken_Access_Control/

---

## 4. OWASP Web Security Testing Guide

The OWASP Web Security Testing Guide provides methodology and guidance
for testing web application security controls.

Official resource:

https://owasp.org/www-project-web-security-testing-guide/

---

## 5. Burp Suite Documentation — Repeater

Burp Suite Repeater is used to manually modify and resend HTTP requests
during authorized security testing.

Official documentation:

https://portswigger.net/burp/documentation/desktop/tools/repeater

---

## Reference Usage

These resources were used to understand:

- Access control
- Object-level authorization
- IDOR vulnerabilities
- Broken Access Control
- HTTP request manipulation
- Burp Suite Repeater
- Web application security testing methodology

---

## Responsible Testing

All testing documented in this repository was performed against an
authorized PortSwigger Web Security Academy lab environment.

The techniques described here should only be used against systems for
which explicit authorization has been provided.
